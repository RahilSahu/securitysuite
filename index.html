Browser & Crawler

Browse the target from inside SecuritySuite. The page is fetched through the selected transport, its links and forms are rewritten, and every page, click and submit is logged to Proxy History, ready for Repeater, Intruder and Scanner.

Fetch-browser · v1.2 · Relay default
Relay: public targets only. LAN / localhost → use Bridge. Relay status shown in the top bar and in the browser meta line below.
How capture works here: there is no iframe spying (browsers block that). SecuritySuite fetches the page via the selected transport, rewrites its links and forms, and renders it below, so navigation stays inside the engine and gets captured. In Relay mode the fetch happens server-side, so the old CORS-blocked message should not appear for public sites — relay errors are shown as relay errors instead. In Direct mode CORS still applies and blocked pages are labelled as CORS-blocked. JavaScript-heavy apps may render partially: fetched scripts never run here, so API calls a page would make from its own JavaScript are NOT captured by the fetch-browser. Hit those endpoints directly in Repeater, or capture the real app traffic with the Proxy Bridge.

Capture · Proxy Bridge

Capture traffic from your phone or another browser on the same network, the same way Burp does: the device sets SecuritySuite's bridge as its WiFi proxy. This is the right transport for LAN / localhost targets that Relay cannot reach.

Select Bridge here when testing LAN targets.
Bridge: not connected
Plain truth: a web page cannot sniff your WiFi or listen for other devices, no website can. The Bridge is a tiny Python script you run on your laptop: devices you configure send their traffic through it, it records everything, and SecuritySuite pulls the capture in live (or via HAR). It only sees devices that set the proxy, nothing else on the network. HTTP is captured in full. HTTPS is tunnelled: hostnames are logged, bodies stay encrypted unless you later add a CA, and the Bridge says so in its log.

1 · Get the Bridge

Single Python file, standard library only, nothing to install. Needs Python 3 on the laptop that will act as the proxy.

View the bridge script

2 · Run it & point your phone at it

  1. On your laptop (same WiFi as the phone): python3 securitysuite_bridge.py. It prints your laptop's LAN IP and a bridge token: keep the token, step 3 needs it.
  2. Phone: WiFi settings → your network → Proxy: Manual → Host = laptop IP, Port = 8080.
  3. Browse or use apps on the phone. Requests flow through the Bridge and are recorded.
  4. Connect below for live import, or press Ctrl+C in the Bridge to save capture.har and import that file in Proxy → Import Traffic.
  5. When done, set the phone proxy back to None.

3 · Connect SecuritySuite to the Bridge

If SecuritySuite is open on the same laptop, use http://127.0.0.1:8899. If it is open on the phone, use the laptop's LAN IP, e.g. http://192.168.1.5:8899. The page polls the Bridge every 3 seconds and imports new captures into Proxy History automatically.

The token is required: the Bridge refuses capture requests without it, so other websites or devices on the LAN cannot read your captured traffic.
